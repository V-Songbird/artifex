# Developing Artifex

Artifex has no dependency installation or source compilation step. Use the Node version in [`.nvmrc`](../../.nvmrc); the minimum supported runtime is declared in [`package.json`](../../package.json). Run commands from the repository root.

## Commands

| Command | Purpose and result |
| --- | --- |
| `npm run check` | Runs lint and the Node test suite, which takes several minutes, so run it with a longer timeout or in the background with its raw output written to a file. |
| `npm test` | Runs `tests/*.test.js`. |
| `npm run test:changed` | Runs only the test files that require or name a file changed against `main`, directly or through other files, and prints which changed scripts no test reaches; `-- --base <ref>` compares with another branch and `-- --list` prints the selection without running it. A change under `core/` still reaches most tests, because the page bundle and the examples load it. A test that lists a directory is not seen, except those the `READS` table in the runner names (today the skill-samples test, for the skill docs and `core/`; the style modules and tools the samples require, spelled `artifex/styles/<file>` or `<library root>/<path>`, are followed from the docs, so a sample that adds a require is covered without editing the table), so run `npm run test:all` before merging. See [`tools/run-tests.js`](../../tools/run-tests.js). |
| `npm run test:all` | Runs every test file the same way. Both commands hold a lock in the system temp directory, so a second run from any worktree waits for the first, and pass `--test-concurrency` at half the machine's threads; `-- --concurrency <n>` sets another cap. |
| `npm run lint` | Checks unread declarations and contract keys. |
| `npm run negative` | Mutates isolated copies and checks which named test rejects each mutation. |
| `npm run page` | Builds the self-contained `out/index.html`. |
| `npm run browser` | Checks the built page in installed Edge using native CDP, including an MP4 film export and decode for every example that declares sound, or for the first with a timeline when none does, and for the first that declares a `reframe` box timeline, each on the encoder colour route unless `--allow-fallback` is passed; prints its summary line and writes the full JSON report to `out/browser.json`, or with `--json` prints the report instead; run `npm run page` first. |
| `npm run browser -- --force no-aac` | Runs the same check with one export fallback forced: `no-aac` on every film the default run exports, `no-webgl2`, `no-h264` or `gpu-crash` on its first. `gpu-crash` hides WebGL2, crashes the GPU process of the check's own Edge once the export has drawn a third of its first pass, and fails unless the film reports its canvas lost and was drawn again in memory. See [the forced fallbacks](verification.md#forced-fallbacks). |
| `npm run browser -- --allow-fallback` | Runs the same check but accepts a film converted on the GPU or CPU, for a machine without a usable GPU. |
| `npm run examples` | Writes registered vector examples as SVG files under `out/`. |
| `npm run seeds -- drift 16 0.5` | Writes a contact sheet for a registered example. `npm run seeds` runs [`tools/contact-sheet.js`](../../tools/contact-sheet.js); there is no `tools/seeds.js`, so call that file with `node` to run it directly. |
| `npm run seeds -- drift 5 0.5 --param reach` | Writes a five-value parameter strip at the piece's fixed seed. |
| `npm run seeds -- drift 3 0.5 --param reach,turn` | Writes a 3-by-3 parameter grid at the piece's fixed seed. |
| `npm run seeds -- refit 9 1 --box 405x720` | Writes a contact sheet at another box of a piece that declares `boxes`. |
| `npm run seeds -- readout --frames 9` | Writes a time strip: nine frames from the first to the last at the piece's seed, 640 pixels wide, each with its draw time, detail and, after the first, its change and hold; `--at 0.5,2,3.25` shows the frames holding those seconds instead. Add `--png` to any seeds command to also write a PNG of the sheet from installed Edge, beside its HTML, named after it; open the PNG to look at the sheet without opening the HTML. A registered example or a style pack writes under `out/`, and a piece you pass by path writes beside itself, except some pieces inside the library, which write under `out/pieces/`; [where output goes](command-line-tools.md#where-output-goes) holds that rule. |
| `npm run seeds -- readout --frames 3 --seed 7` | Draws a time strip, a shot strip or a still at seed 7 instead of the piece's own seed, as `out/readout-frames-seed7.html`, so strips at two seeds keep separate files. A seed sheet refuses `--seed`, and so does a sweep of two `--param` names; a sweep of one name takes it. See [time strips](command-line-tools.md#time-strips). |
| `npm run seeds -- readout --at 2,4 --loupe` | Adds to each frame a 100% crop of the film at its default export scale, around the centre or `--loupe x,y` in design units. |
| `npm run seeds -- ./my-piece.cjs --at 0 --loupe --reference <photo.webp> --png` | Shows a reference photo's centre at 100% as the strip's first cell, the size of each 100% crop, to compare a material with the piece at one scale, as `<name>-at-loupe-reference.png`; `<photo.webp>@x,y` cuts around that point in the photo's pixels, and `--reference-scale 0.5` shows each photo pixel half as wide ([choosing k](command-line-tools.md#time-strips)). Only the crop is embedded in the sheet, never the whole photo. Needs `--loupe`, and installed Edge even without `--png`, because the crop is cut there. |
| `npm run seeds -- specimen --at 0 --loupe --png` | Shows a still as a strip of its one frame, which takes `--scale` and `--loupe`; `--at 0` is the only strip a still takes. |
| `npm run seeds -- readout --frames 9 --png --timeout-ms 240000` | Gives the browser that `--png` starts 240 seconds instead of 60, for costly frames; a run that times out names the stage and cell it stopped in, as [the deadline](command-line-tools.md#contact-sheet-sweeps-and-metrics) describes. A large image is written as several parts; read the names the command prints before copying one. |
| `npm run seeds -- readout --frames 5 --json` | Draws the sheet or strip in installed Edge, as `--png` does, and prints its data as compact JSON on one line (about 20 kB for a 9-by-9 `--param` grid): every cell's marks, build and draw times, and a strip's detail, change, hold and flags, with its sound under `--sound`, and a `profile` of that sound's attack, decay, octave shares and centroid, with the same for a `--sound-reference` file under `window.__sheet.sound.reference`. The summary lines go to stderr, so stdout holds only the JSON. Works alone or with `--png`, and takes `--timeout-ms`. |
| `npm run seeds -- readout --at 2,4 --values` | Adds under each cell its value view: lightness blurred, then cut into 3 levels, with a ring on the peak value step. Works on seed sheets, `--param` sweeps and every strip; `--compare` refuses it. See [value, greyscale and colour-vision views](command-line-tools.md#value-greyscale-and-colour-vision-views). |
| `npm run seeds -- --compare <render.png> <reference.png> [--threshold n] [--json]` | Compares two PNG files of one size pixel by pixel, in Node with no browser: the mean channel difference, the share of pixels off by more than `--threshold` (a plain-decimal channel difference from 0 to under 255, default 32), that share in each region of a grid, and the region most off. `--json` prints the same as JSON. It takes no piece and refuses every other option. |
| `npm run seeds -- <piece> --plan [--seed n] [--json]` | Draws a film's view on every frame over the place as `<piece>-plan.html`, in Node with no browser: a dot at each frame's centre, each beat ringed, each beat's view speed as a share of its camera move's peak, and each shot's subject marks and line of attention. The piece keeps one view per frame in `state.cues.views`, and optional `state.cues.blocking` rows, as the film scaffold does. It takes one piece and refuses every other option. See [planning a film's views](command-line-tools.md#planning-a-films-views). |
| `npm run seeds -- <piece> --shots --cuts [--png] [--json]` | Adds to the shot strip what you need to compose across each cut: the frames either side of each cut blended, the incoming focus ringed, and every eye track on one frame. It writes `<piece>-shots-cuts.html` and refuses `--cuts` without `--shots`. See [cut pairs](command-line-tools.md#cut-pairs). |
| `npm run seeds -- readout --at 2,4 --grey` | Adds under each cell its greyscale view: each pixel replaced by the grey of its OKLCh lightness, so you need no grey parameter of your own. |
| `npm run seeds -- readout --at 2,4 --colour-vision` | Adds under each cell three simulated views: deuteranopia, protanopia and tritanopia. |
| `npm run seeds -- specimen --at 0 --gamut FOGRA39L.txt --json` | Adds under each cell its print-gamut view: each pixel outside an approximate coated-paper print gamut painted magenta, the rest in grey. The gamut comes from Fogra's `FOGRA39L.txt`, which you download; Artifex does not ship it. With `--json`, each drawn cell gains `gamut`: `share` of pixels outside and `excess`, their largest OKLab distance from the gamut. See [print-gamut view](command-line-tools.md#print-gamut-view). |
| `npm run seeds -- tests/fixtures/touching-film.cjs --at 0,0.125 --part red=#f00 --json` | Measures on each drawn frame how much of a named part's area does not show, such as under marks drawn after it; the part is the colour its marks are painted with. Works on any time strip, needs `--json`, and repeats for each part; each cell gains `parts`. See [part coverage](command-line-tools.md#part-coverage). |
| `npm run seeds -- tests/fixtures/touching-film.cjs --at 0,0.125 --figure red=#f00 --png` | Draws under each frame the flat fill of the marks painted in a figure's colours, and measures its gaps, holes, widths, widest single runs and plumb line. Works on any time strip, with or without `--png` or `--json`, and repeats for each figure; the page takes `+figure` at the end of its name, and each cell gains `figures`. See [figure silhouettes](command-line-tools.md#figure-silhouettes). |
| `npm run seeds -- ./my-film.cjs --frames 9 --armature` | Draws under each frame the same frame with its armature's joints, bone axes and section ellipses over it, from the one armature per frame the piece keeps in `state.cues.armature`, and prints its joint faults per frame: a front-view bend joint off the line between its neighbours, a joint past its limit, a segment changing length and a planted end sliding. Works on any time strip, with or without `--png` or `--json`; the page takes `+armature` at the end of its name, and each cell gains `armature`. See [armature overlay](command-line-tools.md#armature-overlay). |
| `npm run seeds -- readout --at 2,4 --sample 100,80 --json` | Reports the OKLab and OKLCh colour at a design point on each drawn frame. Works on any time strip, needs `--json`, and repeats for each point; each cell gains `samples`. See [pixel samples](command-line-tools.md#pixel-samples). |
| `npm run seeds -- ./my-film.cjs --frames 9 --two-values 0.12,0.88` | Reports on each drawn frame the share of pixels between two declared lightnesses, and flags a frame whose share is over 2%. The values can also come from a beat-sheet line. Works on any time strip. See [two values](command-line-tools.md#two-values). |
| `npm run seeds -- readout --frames 9 --sound` | Adds the piece's soundtrack under the strip, levelled as the film's AAC, as `out/readout-frames-sound.html`: a waveform with its loudness over 50 ms, and a spectrogram from 40 Hz to 16 kHz on a log scale. Both span the whole film, with a line at each frame shown and at each shot cut, and each silent stretch of 0.5 s or more shaded. Needs a piece that declares sound. |
| `npm run seeds -- stride --contacts falls --sound --json --sound-reference steps.mp3` | Measures a sound file the way the soundtrack is measured, so one run gives both profiles. It takes a `.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.opus` or `.flac` file, needs `--sound` and `--json`, and decodes the file in installed Edge. Only its numbers go into the sheet, under `window.__sheet.sound.reference`; see [time strips](command-line-tools.md#time-strips). |
| `npm run film -- readout` | Saves a registered example's or an external piece's MP4 film through the page's own export in installed Edge, as `out/readout.mp4` with its report `out/readout.mp4.json` and, for a film with sound, a picture of its decoded soundtrack `out/readout.mp4.sound.png`, and prints one summary line; takes `--out`, `--seed`, `--scale` and `--bitrate`, and `--force no-aac` or `--force no-webgl2` to save the film a browser without AAC or WebGL2 saves, or `--crash-gpu <ms>` to [crash the GPU during the export](verification.md#crashing-the-gpu-during-a-saved-film). |
| `npm run still -- specimen` | Saves one frame of a registered example or an external piece as the page's PNG button saves it, with its replay manifest, as `out/specimen.png`; `--out <name>.svg` saves an SVG from Node instead, and `--seed`, `--at` (seconds) and `--scale` pick the seed, frame and pixels; `--box WxH` draws a piece that declares `boxes` at another box. See [saving a still](command-line-tools.md#saving-a-still). |
| `npm run stitch -- a.mp4 b.mp4 -o film.mp4` | Joins MP4 films Artifex exported at one size, frame rate and codec configuration into one film without encoding again, keeping each scene's recipe; refuses any other film by name and prints how late each later scene's sound starts. See [joining films](command-line-tools.md#joining-films). |
| `npm run replay -- out/readout.svg` | Reads the replay manifest of a saved SVG, PNG, MP4 film or WebM film, draws it again and prints whether the file matches, writing the full JSON report to `replay-<file name>.json` beside the file, or under `out/` when the file is inside the library, or with `--json` printing it on stdout, so stdout holds only the JSON and the verdict and scene lines go to stderr; a file from an external piece needs `--piece ./piece.cjs`, and a [joined film](command-line-tools.md#joining-films) needs one `--piece` per external scene. |
| `npm run image -- photo.jpg --source <text> --rights <text>` | Writes an image the user gives as `photo.image.js`, a module a piece declares in `images`: decoded sRGB pixels, with the source and rights both required. A plain PNG is decoded in Node and any other image in installed Edge. `--width N` shrinks it by area average and `--channels 1` keeps only its tones. See [turning an image into a module a piece declares](command-line-tools.md#turning-an-image-into-a-module-a-piece-declares). |
| `npm run measure -- ref.png` | Measures a PNG reference: its size in pixels, up to 8 dominant colours with their pixel shares (`--colors N`, up to 32), and each colour region's outlines as simplified point lists, as one line of JSON on stdout or in `--out file.json`; writes no picture. JPEG, WebP and GIF files are refused by name. See [measuring a reference image](command-line-tools.md#measuring-a-reference-image) and [reference measurements](../apis/reference-measurements.md). |
| `npm run styles` | Lists the built-in styles and the style packs installed under `~/.artifex/styles` (or `ARTIFEX_HOME`), each with its signature, mark functions and the paths of its guide and module, then broken and refused folders and their reasons; `-- --json` prints the list as JSON. No style draws by name: `--style` in `page`, `seeds`, `still`, `film` and `replay` is refused with those paths. See [style packs](../apis/style-packs.md). |
| `npm run styles -- trust <name>` | Verifies an installed pack's files against its `style.json`, shows them with the modules they require, and records the hash of its `style.json` as trusted. |
| `npm run styles -- check <name>` | Checks a style: a built-in module exports mark functions and no piece, and its guide has every section; a pack matches its hashes, is trusted, has every guide section, loads confined to its files, exports the mark functions its `style.json` lists, and each draws the same twice inside its proof's box. |
| `npm run styles -- pack ./marks.js --proof ./proof.js --name dots --guide ./guide.md --summary "…"` | Makes a pack of a module of mark functions: copies it, its proof and their files with their requires rewritten, writes `style.json`, proves each mark from the copy, and only then installs and trusts it under `ARTIFEX_HOME`. A pack holds no piece or picture. |
| `npm run bench` | Measures build, draw, and vector emission costs. |
| `npm run bench:sim -- --pile bimodal --runs 5 --frames 24` | Times [`simulate`](../../core/sim.js) on seeded piles of discs (`uniform`, `bimodal`, `mixed`, `pegboard`; all four by default), each run in a fresh process, alternating the broad phase with `everyPair`. Prints each variant's median, range, machine CPU load and result digest, and exits 1 if the digests differ. Only `pegboard`, 600 discs falling onto 231 pegs, has enough walls for `simulate` to file them in a grid, so it is the pile that times wall lookups. It is separate from `npm run bench` and writes no baseline. |
| `npm run site` | Builds the showcase site into `out/site/` from `site/shots.js`; `-- --serve` also serves it on loopback. See [the site](site.md). |
| `npm run site:check` | Runs the site's own tests in `site/tests/`, outside the mutation suite. |
| `npm run posters` | Draws the site's posters in installed Edge from the recipe in [the site](site.md#the-art-shots) and writes each that changed, with its recipe record, under `site/posters/`; each record holds a hash of every source its poster bundles, `core/` included, so run it after editing any of those sources and commit the records with the change. |
| `node tools/check-site.js` | Checks the built site in installed Edge: scroll, draws, reduced motion, the worker fallback, recipes, Listen (no audio before the press, two renders of every soundtrack bit-identical, "Play as film" within one frame of its sound) and the frame budget on two references; run `npm run site` first, and not again until the check ends, because the check serves `out/site/` and a rebuild replaces that folder. |

The benchmark uses a null surface to measure drawing calls without SVG emission. For vector pieces, the displayed emission cost excludes that draw time. The total is build plus full vector rendering; for raster-only pieces it is build plus null-surface drawing. It does not measure browser canvas or video encoding performance. Inspect [`tools/bench.js`](../../tools/bench.js) before choosing benchmark flags or comparing its baseline.

`npm run bench` writes or replaces `out/bench.json`. `BENCH_REPS` controls its sample count and defaults to 40. Preserve a baseline elsewhere before running a comparison you need to retain.

For a focused contract check, run `node --test tests/piece.test.js`. A stopped `node --test` names only the file, even with `--test-timeout`; to name a hanging test, run each title alone with `--test-name-pattern` under a timeout. Generated pages, artwork, contact sheets, and benchmark results go under `out/`: the library's own when a command runs from inside the library, and the `out/` of the folder it runs from otherwise, so an installed plugin never holds output ([where output goes](command-line-tools.md#where-output-goes)).

## Rules for every change

After source changes, run `npm run lint` and `npm run test:changed`. Before merging, run `npm run lint` and `npm run test:all`. Both test commands wait for any other run on the same machine, so worktrees never run two suites at once. CI still runs `npm run check`. Run the mutation suite when changing a check, contract key, or invariant; it runs the whole suite once as a control, then, for each mutation, the test file that holds its expected test, and takes longer than the unit suite. After editing a line that a mutation in [`tests/negative.js`](../../tests/negative.js) patches, run `node --test tests/mutation-patches.test.js` first; it names each stale patch text in under a second. A test that a mutation expects must fail in well under 1 MiB of output, the [runner's cap](verification.md#the-mutation-suite), so compare large arrays such as pixels or frames by a count or the first differing index, not `deepEqual`, or the mutation reports as infrastructure (`ENOBUFS`) instead of caught.

Core helpers must remain useful across subjects. Keep algorithms specific to an example with that example. When the public contract changes, reconcile the [piece API](../apis/piece-api.md) and the [runtime skill](../../skills/artifex/SKILL.md), with its references, with `FIELDS`.

Read [verifying changes](verification.md#focused-checks-by-area) for the tests that cover the area you change, and [what verification establishes](verification.md#what-verification-establishes) before claiming a browser, export or visual result.

## Plugin metadata

Two manifests describe the plugin:

- [`plugin.json`](../../plugin.json) at the root, in the open Agent Plugins 1.0 format. Codex, Antigravity and Cursor read it. Its `extensions.com.openai.interface` block holds what Codex shows (display name and category), so there is no separate `.codex-plugin/plugin.json`: Codex reads that file only when the block is absent.
- [`.claude-plugin/plugin.json`](../../.claude-plugin/plugin.json), the only manifest Claude Code reads.

The [Claude marketplace catalog](../../.claude-plugin/marketplace.json) and [Codex marketplace catalog](../../.agents/plugins/marketplace.json) identify `artifex` with a source of `./`, the repository they sit in. There is no Gemini CLI manifest.

The version is stated in both manifests, in `package.json` and in each skill's `metadata.version`; bump them together. Claude Code pins users to the manifest version, so a release that forgets one never reaches them. `node --test tests/plugin-manifests.test.js` fails when a name, version or description differs anywhere, and `node --test tests/skill-limits.test.js` fails when a `SKILL.md` body reaches 24,000 bytes (Antigravity loads no more) or its frontmatter breaks the Agent Skills limits.

The icon is an Artifex piece, [`assets/icon.cjs`](../../assets/icon.cjs), saved as `assets/icon.png` (1024 px) and `assets/icon.svg`. Claude Code finds `assets/icon.png` by its path, and Codex reads the `logo` and `composerIcon` paths in its interface block. Antigravity shows a generic icon: it takes one only from a `logo` field, which the Agent Plugins 1.0 schema of the root manifest does not allow. After changing the piece, draw both files again with `npm run still -- assets/icon.cjs --out assets/icon.png` and the same command with `assets/icon.svg`, then check each with `npm run replay -- assets/icon.png --piece assets/icon.cjs`.

The skills need the whole plugin: they find the library as the nearest folder above `SKILL.md` that holds `core/piece.js`, and a skill folder copied alone has none. Distribution is the Git repository only; a local-path install is for development, because a host may copy files Git does not track.

Parsing these files proves their structure, not installation or discovery in a running host.

[`AGENTS.md`](../../AGENTS.md) is the agents' map of the repository and links here; [`CLAUDE.md`](../../CLAUDE.md) imports it for Claude Code. Host settings and plugin installation are separate from the library's runtime requirements.
