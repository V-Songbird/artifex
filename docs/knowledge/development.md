# Developing Artifex

Artifex has no dependency installation or source compilation step. Use the Node version in [`.nvmrc`](../../.nvmrc); the minimum supported runtime is declared in [`package.json`](../../package.json). Run commands from the repository root.

## Commands

| Command | Purpose and result |
| --- | --- |
| `npm run check` | Runs lint and the Node test suite. |
| `npm test` | Runs `tests/*.test.js`. |
| `npm run lint` | Checks unread declarations and contract keys. |
| `npm run negative` | Mutates isolated copies and checks which named test rejects each mutation. |
| `npm run page` | Builds the self-contained `out/index.html`. |
| `npm run browser` | Checks the built page in installed Edge using native CDP, including an MP4 film export and decode for every example that declares sound, or for the first with a timeline when none does, each on the encoder colour route unless `--allow-fallback` is passed; prints its summary line and writes the full JSON report to `out/browser.json`, or with `--json` prints the report instead; run `npm run page` first. |
| `npm run browser -- --force no-aac` | Runs the same check with one export fallback forced: `no-aac` on every film the default run exports, `no-webgl2` or `no-h264` on its first. |
| `npm run browser -- --allow-fallback` | Runs the same check but accepts a film converted on the GPU or CPU, for a machine without a usable GPU. |
| `npm run examples` | Writes registered vector examples as SVG files under `out/`. |
| `npm run seeds -- drift 16 0.5` | Writes a contact sheet for a registered example. |
| `npm run seeds -- drift 5 0.5 --param reach` | Writes a five-value parameter strip at the piece's fixed seed. |
| `npm run seeds -- drift 3 0.5 --param reach,turn` | Writes a 3-by-3 parameter grid at the piece's fixed seed. |
| `npm run seeds -- refit 9 1 --box 405x720` | Writes a contact sheet at another box of a piece that declares `boxes`. |
| `npm run replay -- out/readout.svg` | Reads the replay manifest of a saved SVG, PNG, MP4 film or WebM film, draws it again and prints whether the file matches, writing the full JSON report to `out/replay-<file name>.json`, or with `--json` printing it. |
| `npm run bench` | Measures build, draw, and vector emission costs. |
| `npm run site` | Builds the showcase site into `out/site/` from `site/shots.js`; `-- --serve` also serves it on loopback. See [the site](site.md). |
| `npm run site:check` | Runs the site's own tests in `site/tests/`, outside the mutation suite. |
| `npm run posters` | Draws the site's posters in installed Edge from the recipe in [the site](site.md#the-art-shots) and writes each that changed, with its recipe record, under `site/posters/`. |
| `node tools/check-site.js` | Checks the built site in installed Edge: scroll, draws, reduced motion, the worker fallback, recipes and the frame budget on two references; run `npm run site` first. |

Run `npm run check` after source changes. Run the mutation suite when changing a check, contract key, or invariant; it executes a full test run for each mutation and takes longer than the unit suite.

The benchmark uses a null surface to measure drawing calls without SVG emission. For vector pieces, the displayed emission cost excludes that draw time. The total is build plus full vector rendering; for raster-only pieces it is build plus null-surface drawing. It does not measure browser canvas or video encoding performance. Inspect [`tools/bench.js`](../../tools/bench.js) before choosing benchmark flags or comparing its baseline.

`npm run bench` writes or replaces `out/bench.json`. `BENCH_REPS` controls its sample count and defaults to 40. Preserve a baseline elsewhere before running a comparison you need to retain.

For a focused contract check, run `node --test tests/piece.test.js`. Generated pages, artwork, contact sheets, and benchmark results go under `out/`.

## External pieces

`npm run page -- ./piece.cjs` and `npm run seeds -- ./piece.cjs 9 0.5` accept a CommonJS module exporting one piece. From another project, use `npm --prefix "/path/to/artifex" run page -- "./piece.cjs"` or the equivalent `run seeds --` command, replacing the library path. These npm commands resolve relative input paths against npm's original invocation directory (`INIT_CWD`); direct Node commands use their current directory. Quote paths containing spaces.

External outputs are written beside the resolved source module: `piece-page.html`, `piece-seeds.html`, or `piece-param-width-height.html` for `--param width,height`. Output stems come from the source filename, replacing filesystem-reserved characters. Parameter-name suffixes are URL-encoded, including `*` as `%2A`, so names cannot introduce Windows wildcard characters or path separators. Existing files with the same generated name are replaced. The registered-example defaults still write under the library's `out/`; `examples` and `bench` still operate only on the example registry.

The loader supports a restricted CommonJS subset: direct literal `require('...')` or `require("...")` calls, including relative helpers, absolute library imports and JSON data. `require('artifex/core/<file>.js')` names a module in the library's `core/` from any folder; a name `core/` does not hold is refused. Helpers must be browser-compatible `.js` or `.cjs` modules. It is not a general CommonJS bundler. Node builtins, native modules, ESM syntax, require aliases and computed require paths are rejected. Shadowed/local functions named `require` and require calls inside template interpolation are unsupported; keep imports as ordinary calls outside templates.

Node runs an external piece from the same module table and module text the page gets, not through Node's own `require`, so both load the same sources. A module sees only `module`, `exports` and `require`: Node's module globals such as `__dirname`, `__filename` and `require.resolve` are absent in Node as in the page, and reading one fails the load. Library modules are the files the page bundles. `loadExternal(input, cwd, { confine: { root, files } })` confines a load to `files`, paths relative to `root` with forward slashes, and to `artifex/core/<file>.js`: a piece outside the list, and every other require, including another library file, an absolute path, a package or a path out of `root`, is refused by name.

Inline script-end text in ordinary quoted strings is escaped without changing its value. Any template literal containing literal `</script` text is rejected, whether tagged or untagged; use ordinary quoted strings or JSON for that data. This conservative rule avoids changing raw template strings while trying to infer their tag. Templates without that marker remain supported. Emitted scripts are parsed before writing, and malformed JSON errors identify the data file and retain the original parse cause. The generated HTML includes its module sources and needs no filesystem access when opened. Piece loading executes trusted local code in Node, where globals such as `process` remain reachable; this is not sandboxing.

In PowerShell, use `npm.cmd` when forwarding options such as `--param`; a PowerShell npm shim may consume the `--` separator before npm sees it. For example: `npm.cmd --prefix "/path/to/artifex" run seeds -- "./piece.cjs" 3 0.5 --param width`.

Parameter strips and grids use the same `--param` option and fixed-seed rules for external pieces. Run `node --test tests/external-piece.test.js tests/contact-sheet.test.js` for module loading, the `artifex/core/` import, Node and page parity, confinement refusals, nested dependencies, invocation paths, filenames, error cases and sweep contracts. Inspect the generated page and sheet in a browser to verify native rendering.

## Contact-sheet sweeps and metrics

`npm run seeds -- <piece> [count] [playhead] --param <a>[,<b>]` samples one or two declared parameter ranges evenly, including their exact minimum and maximum. It requires one registered example and distinct, declared parameter names. `count` is samples per axis (default 3, minimum 2), so a two-parameter sweep has `count * count` cells. The first parameter runs across columns; the second runs down rows. The sheet preserves those axes with keyboard-accessible horizontal scrolling on narrow screens. Other parameters retain their declared defaults, and every cell uses the piece's declared seed.

`--box WxH` draws every cell of one piece at that box, refused by name unless the piece declares `boxes` holding it, and adds the box to the file name, such as `out/refit-seeds-405x720.html`.

Without `--param`, the existing behavior remains: `count` defaults to 9 and cells use seeds 1 through `count`. The playhead defaults to 1 in either mode. Parameter output names include the selected parameters, such as `out/drift-param-reach-turn.html`; seed output remains `out/drift-seeds.html` (or `out/seeds.html` for all examples).

Each cell labels the varied values and reports three diagnostics:

- **Marks:** successful canvas paint calls (`fill`, `stroke`, `fillRect`, `strokeRect`, `drawImage`, `fillText`, `strokeText`, `putImageData`). A call can paint no visible pixels; this is not an object count. Background paint calls count.
- **Bbox coverage:** the area of the bounding rectangle around final nontransparent pixels, divided by raster canvas area. It includes background pixels: a fully painted background gives 100%. It is not ink density, foreground segmentation, or a quality score. Bounds are sampled at the preview's raster resolution, 480 pixels wide.
- **Build ms:** elapsed time around `solve`, including state creation and the build stages, excluding drawing and pixel measurement. Timing varies between runs.

`window.__sheet` retains `names`, `count`, `t`, and `failures()`, and adds `paramNames` and `cells`. Successful cell records carry `name`, `seed`, resolved `params`, quantized `t`, `buildMs`, `markCount`, `bbox` in raster pixels (null when empty), `coverage` in [0, 1], `rasterSize`, and `error: null`. Failed cells retain their inputs and an error message; later cells still render. These data let an agent filter candidates before visual review, without treating the metrics as artistic judgment.

Run `node --test tests/contact-sheet.test.js` for argument, sampling, determinism, metric, and bundle-parsing checks. Actual raster output and native canvas behavior require browser verification.

Add `--png` to any `npm run seeds` command to also write a PNG of the sheet beside its HTML, with the same name, such as `out/drift-seeds.png`. A sheet of several pieces gets one image per piece, such as `out/seeds-drift.png`, so each stays readable. It opens the sheet in installed Edge with the browser check's own lifecycle (a unique temporary profile, a loopback server and the same cleanup), waits until `window.__sheet` holds every planned cell, each drawn or failed, and captures the whole page at one device pixel per CSS pixel. Seed sheets are 1280 pixels wide; a sweep is wide enough for every column (48 + 220 per column + 14 per gap), and 1280 at least. An image taller than 8192 pixels is scaled down to that height. An image too heavy for one browser reply (about 3 MB of PNG) is written top to bottom as `<name>-1-of-<n>.png` and on, each file one screenshot. The HTML sheet and `window.__sheet` are unchanged. `node --test tests/contact-sheet.test.js tests/check-browser.test.js` checks the option, the names, the widths and the wait condition; the image itself needs installed Edge.

## Replaying a saved file

`npm run replay -- <file> [--piece ./piece.cjs] [--edge PATH] [--timeout-ms N] [--headed] [--json]` reads the replay manifest a saved SVG, PNG, MP4 film or WebM film carries, draws its recipe again and reports whether the file matches; [output formats](output-formats.md#replaying-a-saved-file) describes what each type proves and its limits. Pass `--piece` with the module that made a file from an external piece. Relative paths resolve from npm's invocation directory, as for `page` and `seeds`. A PNG or film replay starts installed Edge through [`tools/check-browser.js`](../../tools/check-browser.js), which takes the same `--edge`, `--timeout-ms` and `--headed` options; an SVG replay needs no browser. The command prints a verdict line and the absolute path of its full JSON report, written to `out/replay-<file name>.json` in the library, such as `out/replay-readout.svg.json`, and replaced on the next replay of a file with that name. `--json` prints the JSON report before the verdict line instead and writes no file. Either way it exits nonzero when the file differs or cannot be replayed; a file that differs is named with its first difference in the verdict line, and one that cannot be replayed on standard error.

Run `node --test tests/replay.test.js` for manifest reading, the version, piece, box, outputs, scale, size and frame-grid refusals, the SVG round trip, the WebM seek times, the PNG and film verdict rules, the soundtrack's levelling, gain and limiter, as the export applies it, its block verdicts, a noise fixture's noise-like bands judged by waveform and level and still refusing a moved tone, another noise, a missing voice, a voice in another band and one 6 dB louder or quieter, a hi-hat low-passed as a codec cuts it judged only below the band the film kept, those refusals and a different hi-hat still refused under that cut, no cut taken under 12 kHz, for a missing voice or for a gentle low-pass, a block judged without its mean, the rule that a film and its piece agree on a soundtrack in a codec the export writes, pictures named before the soundtrack, and a WebM frame whose read throws still closing its `VideoFrame`. The Node tests make their own files and do not start a browser; decoding a PNG or a film and comparing its pixels or frames needs `npm run replay` with installed Edge. To see where a codec cuts, build the page of [`tests/fixtures/noise-film.cjs`](../../tests/fixtures/noise-film.cjs) with `npm run page -- tests/fixtures/noise-film.cjs`, save its MP4 film and replay it with `--piece tests/fixtures/noise-film.cjs`; the report's `sound.cut` is the frequency it judged below.

Run `node --test tests/sound.test.js` for its tree; `tests/examples.test.js` checks that no input in an example's soundtrack takes more than two connections. Whether two renders are byte-identical needs installed Edge.

The page builder discovers JavaScript modules in `core/` and `examples/`, then bundles them with a CommonJS loader. Its module-resolution and script-parsing checks catch structural build failures. Template-string content needs correct escaping before it becomes browser JavaScript.

Address-bar synchronization is best effort: documents that reject `history.replaceState` still support selection, playback and exports, but cannot update shareable recipe URLs.

When building a selected piece fails, the page preserves the original build diagnostic and clears its canvas and measurements. Playback and exports are disabled until a valid rebuild or selection succeeds; `read().error` retains the diagnostic and `manifest()` returns `null`. Direct video requests reject with that diagnostic instead of exporting partial state. Run `node --test tests/page-build-errors.test.js` for this error/recovery contract.

MP4 export runs through [`core/film.js`](../../core/film.js) with the browser encoders and decoder passed in, so `node --test tests/film.test.js` checks the writer, the reader, the file check, timestamps, colour tagging, the encoder route's test patterns and fallback, soundtrack length, the film length and soundtrack edit list, the loudness meter and the soundtrack's levelling, and the replay manifest against controlled encoders. The levelling tests hold the limiter to -14 LUFS under -2 dBTP on synthesized drums, speech-like bursts and clicks, to its 12 dB depth, to meeting each peak ahead of it on both channels and from the first sample, and to its 50 ms release. Native encoding, decoding and playback need `npm run browser` or a browser. To hear the limiter, export the MP4 film of [`tests/fixtures/drum-film.cjs`](../../tests/fixtures/drum-film.cjs) or [`tests/fixtures/speech-film.cjs`](../../tests/fixtures/speech-film.cjs) from its page, as for the noise fixture above, and replay it with `--piece`; the export's report gives `sound.limited`. Frame timing read in a browser measures rasterization only when the work is forced first, for example by a one-pixel `getImageData`; a clock read after the drawing calls return measures their submission.

## What verification establishes

The Node suite checks selected contract, geometry, replay, frame-grid, SVG, and example properties. Its browser-facing tests use controlled surfaces and script inspection. They do not launch a browser or establish visual quality.

`npm run browser` requires Node 22 or later and an installed Microsoft Edge. It uses native `fetch` and `WebSocket`, with no package dependency or browser download. It serves the built HTML snapshot on an OS-assigned loopback port and launches Edge with a unique temporary profile. Existing browser sessions and profiles are left alone. `--edge PATH` or `EDGE_PATH` selects another Edge installation; `--timeout-ms 60000` sets the startup/navigation/evaluation deadline (100–300000 ms), `--headed` shows the browser, `--force` forces one export fallback, `--allow-fallback` accepts a fallback colour route (both below), and `--json` prints the full JSON report before the summary line instead of writing it to a file. Without `--json` the command prints its summary line and then `report: ` with the absolute path of `out/browser.json` in the library, which each run replaces. Pass options after `npm run browser --`. Cleanup has a separate bounded grace period and failures exit nonzero with diagnostics.

Cleanup stops only the Edge process the check launched and its descendants, never Edge by executable name. On Windows it runs `taskkill /T /F` on that process and then waits up to 180 seconds for that process to exit; `taskkill`'s exit code and localized output decide nothing, because it also fails for a member that exited by itself. A kill command that cannot start fails cleanup. Under heavy CPU load an owned Edge has taken over two minutes to exit. A process that is still running at the limit fails cleanup. The check then removes only its own `artifex-browser-*` profile under the system temporary directory, retrying busy or locked files for up to 120 seconds while stopped processes release them; a descendant that outlived Edge keeps the profile locked, so the removal then fails cleanup. When every check passed and only cleanup failed, the command still prints its summary line, marked `cleanup failed`, and the report (or its path), and exits nonzero. A failed check prints no report and names its failure on standard error.

The browser command selects every registered example, checks `read()`, each declared stage through `inspect()`, and `manifest()`, confirms the HTTP recipe URL, and draws into a separate native canvas with `willReadFrequently: true`. It reports nontransparent pixel counts, including backgrounds. For a piece that declares `boxes`, it also sets a narrower box through `__artifex.setBox`, requires the page's canvas, `read()`, `manifest()` and address bar to name that box, and draws the piece natively at it. It then exports a film through `__artifex.film()` for every example that declares sound, or for the first with a timeline when none does. For each film it requires the page to offer that example's MP4 film and hide the WebM fallback, decodes the film in the page, requires the first, middle and last decoded frames to resemble their own drawn frames at least as closely as their neighbours (a held frame ties with an identical neighbour), requires a declared soundtrack to decode to exactly the film's length, within one sample; two more renders of it in the page to hold the same bits in every sample, naming the channel, sample and both values of the first difference otherwise; one of them, levelled in the page with `__artifex.level`, gain and limiter, to report the export's `measured`, `gain`, `limited`, `lufs`, `dbtp` and `short`; the soundtrack to follow that levelled render for 1024 samples from its first sound, at 10 dB signal to error or better; and to measure -14 LUFS within 0.1 once decoded, or, quieter than that, peak no more than 0.1 dB under the -2 dBTP ceiling for AAC or 0.15 dB for Opus, and to decode under -1 dBTP in any case; and requires the replay manifest found in the film's bytes to equal the page's recipe. The loudness rule, `loudnessMatch`, also requires the export's report to carry `short` exactly when the level it encoded the soundtrack at is more than 3 LU under -14 LUFS; at exactly -17.00 LUFS it takes either, because that level is rounded and `short` is measured before rounding. Each film's sound report carries `short` and `limited` when the export gave them. `frameMatch`, `soundMatch` and `loudnessMatch` run in the page from their source text, and `node --test tests/check-browser.test.js` checks each of them, and that the page's film check acts on the loudness verdict, carries `short` and `limited`, and refuses a fresh levelling that reports otherwise than the export, against a controlled page. Each film's report names the colour conversion route it took, and every MP4 film must take the encoder route, which installed Edge supports. Its fallbacks to the GPU or CPU conversion keep a film correct and only slow the export, so without this requirement a browser or code change that stopped the route would pass. On a machine without a usable GPU, `--allow-fallback` accepts either fallback; the report then carries `allowFallback: true`, and the summary line says `accepting a fallback colour route`. Page exceptions, console errors, failed checks and timeouts fail the command. This smoke check does not verify composition, cross-browser or physical-device behavior, or how a film plays on another device, and without `--force no-h264` it does not verify the WebM fallback or its timing. The ordinary Node suite and current CI do not require Edge.

Each checked frame is compared at 240 pixels wide with references drawn on the kind of canvas the export drew the film on: a GPU-backed canvas, or one kept in memory on the CPU colour route, because translucent drawing rasterizes differently on each. They are read through a separate small memory canvas, because reading a GPU-backed canvas with `getImageData` moves it to memory for good. Each decoded frame is read through a `VideoFrame` made from the video element and closed once read, here and in `npm run replay`'s film comparison. Drawing the element itself can convert a software-decoded frame's colours away from the pixels it carries (see [WebM](output-formats.md#webm)). A decoded frame matches when it scores at least 30 dB PSNR against its own drawn frame and no neighbour scores higher. The exported films measured 40 to 54 dB in installed Edge; a reference drawn from another seed scored 25.6 dB against readout's middle frame. The report lists each checked frame's `psnrDb` and its closest neighbour's `neighbourDb`.

`npm run browser -- --force <condition>` installs one condition in the page before it loads, through `Page.addScriptToEvaluateOnNewDocument`, and checks the fallback it causes on the first film the default run would export, or with `no-aac` on every film it would export, so that every limited soundtrack, as settle's and cues' are, is decoded as Opus too. The conditions take one thing away and leave the rest to Edge: `no-aac` makes `AudioEncoder.isConfigSupported` refuse every `mp4a` configuration, `no-webgl2` makes `getContext('webgl2')` return `null` on canvases and offscreen canvases, and `no-h264` makes `VideoEncoder.isConfigSupported` refuse every `avc1` configuration. With `no-aac` each film must carry an Opus soundtrack, pass the soundtrack checks above and, without `--allow-fallback`, take the encoder route as a default run's films do; with `no-webgl2` its report must name the CPU colour route, with or without `--allow-fallback`, and its decoded frames must pass the frame check. With `no-h264` the page must offer the WebM film for the H.264 reason and hide MP4; one recording through `__artifex.video()` must decode, last `frames / hz` seconds as the element reports it, pass the frame check, and hold every frame, evenly spaced, when its saved bytes are read in Node with the page's `webmBlockTimes` and `filmVerdict`. A forced run checks every example as the default run does, names its condition in the report's `forced` field and its summary line, which starts `browser with AAC refused`, `browser with WebGL2 hidden` or `browser with H.264 refused`, and takes one condition at a time. The WebM recorder paces frames by the wall clock, and the page refuses a recording that fell behind its schedule, which heavy CPU load causes. The `no-h264` run then records again, at most three recordings in all, and names each refusal with the frames it held in the film's `refusals` and in the summary; it fails at once on any other refusal, and on a third refusal. The recording the page accepts is judged as above.

For browser or export changes, inspect actual rendered output and saved files. Check exported video frame counts and spacing from the encoded file. Automated numerical checks do not establish composition, layering, or usability.

The mutation suite copies `core/`, `examples/`, `tests/`, `tools/`, and `package.json` into temporary directories. Its control requires exit 0 and a complete, nonempty Node TAP report. A mutation is caught only when a completed exit-1 test run reports its named assertion; a completed passing run is escaped, and a different failed assertion is misnamed. Launch errors, signals, unexpected exit codes, and incomplete or inconsistent TAP are infrastructure failures, including when some failures were printed before the process stopped. The runner keeps process metadata and both output streams, reports infrastructure failures separately, and exits unsuccessfully. A control with failing tests prints each failed title with its TAP diagnostic: the assertion message, expected and actual values, and location. Misnamed and infrastructure lines print the same diagnostics for the failures they did see. Run `node --test tests/negative-runner.test.js` for bounded process and report regression checks.

Every infrastructure result, for the control or a mutation, is kept under the run's temporary root in `infrastructure/control` or `infrastructure/m<index>`: `stdout.tap` holds the captured TAP stream, `stderr.txt` the standard error, and `result.json` the exit status, signal, error, failure reason, deadline and PID. The report line names that directory. Each mutated copy is removed as soon as its verdict is printed and its evidence kept, so a run holds the control and at most one mutated copy at a time; a copy that cannot be removed is reported as an infrastructure failure that names it. Final cleanup removes the control and anything left, and removes the temporary root only when nothing was kept; the summary then names the kept `infrastructure` directory.

A mutation's infrastructure result runs its suite once more, for the report only. The line shows the second verdict as `retry, report only: <verdict>`, and a second infrastructure result is kept in `m<index>-retry`. The mutation still counts as an infrastructure failure whatever the retry shows, because a pass under the same load cannot prove the first run harmless and letting it change the verdict would hide load failures. The retry still tells a load-sensitive failure (retry caught) from one the mutation itself causes (retry infrastructure again). A control infrastructure result is kept but not retried: the run stops with exit code 2 either way.

`npm run negative -- --file <path>` runs the control and only the mutations of that repository file, and `--expect <text>` only those whose expected test title contains the text. Repeating an option widens it; giving both requires both. The filter is checked before anything is copied, and one that matches no mutation exits 2 and names the filter. Every other mutation's patch text is still checked, so a stale mutation elsewhere still fails the run. Selected mutations keep their full-run indices, verdicts, evidence paths and exit codes. The control line says how many of the registered mutations were selected, and the summary line of a filtered run starts with `partial run`, so it cannot pass for the full suite. In PowerShell, forward the options with `npm.cmd`.

`npm run negative -- --shard <k>/<n>` keeps the k-th of every n mutations in registry order, so shards `1/n` to `n/n` hold each mutation exactly once. It narrows `--file` and `--expect` by the mutation's full-run index, is given at most once, and is part of the filter a partial run names. Every shard runs the control and checks every patch text.

Expected mutation titles must be unique among all TAP results and exclude control characters and literal control escapes such as `\n`. Node 22 can encode distinct original titles identically. The runner reports ambiguous attribution as an infrastructure failure rather than claiming that the intended assertion failed.

Each test-suite subprocess has a five-minute deadline. Set `ARTIFEX_NEGATIVE_TIMEOUT_MS` to an integer from 1 to 2147483647 to override it; zero does not disable the limit. On timeout the runner reports infrastructure failure, terminates only its owned Windows process tree or POSIX process group, and allows up to thirty additional seconds for teardown, because CPU load can delay `taskkill` itself by seconds. The stop is judged only by the suite process the runner started: it must have exited, or exit within five seconds of the kill ending. `taskkill`'s exit code and localized output decide nothing, because `taskkill` also fails when a tree member exits by itself mid-kill. Node runs each Windows child in a kill-on-close job, so the suite's own descendants end with it; one that kept running would still hold the copy, whose bounded removal then fails the run. A kill command that cannot start is a termination failure, and failed termination remains an infrastructure error. Combined stdout and stderr are capped at 1 MiB. Mutation subprocesses run sequentially. The runner always attempts cleanup of its own temporary copy before reporting its exit code. A stopped Windows process can hold that copy briefly after the runner sees it close, so cleanup retries busy or locked removals for up to ten seconds.

The runner's temporary root is named `artifex-neg-<runner pid>-*`. Each suite runs with `TEMP`, `TMP` and `TMPDIR` pointing to a `t` directory inside its own copy, so fixtures and other temporary files a killed suite never removed go with the copy. A run that is itself stopped before its cleanup leaves its root behind; the next run removes the copies of every such root whose runner process has exited. It never touches a root whose runner is still running, a root without a runner pid in its name, or anything else in the temporary directory. Kept `infrastructure` evidence is never removed automatically: it stays until someone deletes it, so a report's named path remains readable. A suite run directly with `node --test` and killed mid-test still leaves its fixtures in the system temporary directory. The names are short because Windows' `mkdtemp` and process working directories fail past 260 characters, and a runner test nests a whole run of its own inside a copy; with a `TEMP` of up to 120 characters, every path a run creates stays under that limit, which a runner test checks. Roots named `artifex-negative-<pid>-*` by earlier versions are not swept.

## Continuous integration

The [Check workflow](../../.github/workflows/check.yml) uses the Node version in `.nvmrc` on Linux and Windows. The `Mutations (<os>, <k>/8)` jobs run the mutation suite in eight shards per operating system, each with a 90-minute cap. A shard holds every eighth mutation in registry order, so its size is the registry's count divided by eight, rounded up. Hosted runners took about 34 seconds per mutation on Linux and 45 on Windows, measured when the registry held 406 mutations; at that rate a 90-minute Windows shard fits about 120 mutations, or about 960 across eight shards. Each mutation reruns the whole Node suite, so the time per mutation grows as tests are added. Add shards, in the matrix, the job name and the run step, when the longest shard job nears its cap. After them, each `Check (<os>)` job rejects tracked ignored files, runs `npm run check`, builds the standalone page, builds the showcase site and runs `npm run site:check`, and fails unless every mutation shard on both systems succeeded, so the required checks still cover the whole suite. It has a 30-minute cap; each mutation-suite subprocess also retains the finite runner deadline described above.

Submit changes through a pull request targeting `main`. The branch rules require the Linux and Windows checks, resolved review conversations, and a linear history. Deletion and force pushes are blocked.

See the [security policy](../security.md) for private vulnerability reporting and the boundaries of executing piece code.
